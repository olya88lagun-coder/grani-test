# «Мой финансовый компас» — глава «Деньги»

Ветка `codex/money-compass`, база `master` / `2be49c4`. Реализована только глава «Деньги». Остальные три главы сохраняют текущие тексты и поведение. Продакшен не изменён.

## Пользовательский сценарий

1. Пять наблюдений по сохранённым шкалам Big Five; каждое сформулировано как гипотеза для проверки.
2. Шесть вопросов о планировании расходов, непредвиденной трате, настроении, паузе, общих расходах и проверке условий. В каждом есть вариант «Пока не знаю». Ответы можно менять.
3. Четыре направления компаса, доступные кнопками и с клавиатуры. Каждое объясняет вывод и показывает конкретные ответы, на которых он основан.
4. Четыре ситуации: необязательная покупка, неожиданная трата, общие расходы, незнакомое предложение. Шаг меняется по связанному ответу.
5. Выбор одной из четырёх привычек, начало эксперимента, семь отдельных отметок и заметок, итог недели. Даты отсчитываются от локального дня начала. Отметки — собственные записи пользователя, без оценки дисциплины.
6. Персональная памятка из текущих ответов, привычки и итога недели. Её можно редактировать, копировать и скачать как текст. Замена отредактированного текста требует подтверждения.
7. Повторный вход возвращает серверный прогресс. Один результат хранит один эксперимент; интерфейс не сбрасывает его при возвращении.

## Общая архитектура практикумов

- `packages/core/src/practice.ts`: отдельный контракт интерактивных данных.
- `packages/db/src/practice.ts`: общее хранилище черновиков с атомарной проверкой ревизии.
- `practice_drafts`: уникальная пара `result_id + practice_key`, `schema_version`, `revision`, JSON интерактивных данных и время обновления. Удаление результата удаляет приватный черновик каскадом.
- `apps/web/src/server/practice-service.ts`: реестр реализованных практикумов, проверка владельца результата, прежнего доступа к главе и структуры данных. Зарегистрирован только `money`.
- `/api/report/[resultId]/practice/[practiceKey]`: приватные чтение/запись. Неизвестная глава закрыта. Новые главы должны добавить свой контракт, валидатор и интерфейс; хранилище, ревизии и проверки доступа остаются общими.
- `use-practice-draft.ts`: общий клиент сохранения. Изменения отправляются последовательно, с задержкой 700 мс. Неопределённое подтверждение и конфликт показываются отдельно от успешного сохранения.
- `/report/[resultId]/practice/money`: отдельный маршрут с серверной проверкой доступа. В карточке прежней главы появилась ссылка на практикум; сам основной разбор сохранён.

Старые JSON `reports.sections`, результаты теста, покупки, платёжные идентификаторы и черновик атласа не преобразуются и не переписываются. Ранее созданная глава дополнительно доступна в раскрываемом блоке.

## Доступ и цены

Владелец результата с успешной покупкой `chapter_money` или `chapters_all` получает улучшение без новой покупки. Дата покупки не ограничена. Готовность старого сгенерированного отчёта не влияет на доступ к практикуму. Проверяется существующая функция `unlockedKinds` и прежний реестр покупок; возврат покупки закрывает доступ, сохраняя черновик.

Сохранены: глава 99 ₽, комплект четырёх глав 249 ₽, основной разбор 299 ₽. Для новых покупок действует прежний порядок: полный разбор перед главами. ЮKassa, обработчик уведомлений, очередь генерации и основной разбор не менялись.

## Интерпретации

Наблюдения Big Five используют существующие категории `traitLevel`; шкалы теста не становятся финансовыми баллами. Компас использует только ответы на дополнительные вопросы:

| Направление | Вопросы |
| --- | --- |
| Ясность расходов | 1, 2 |
| Пауза перед покупкой | 3, 4 |
| Свои границы | 5 |
| Проверка условий | 6 |

Нет ответа — «Ждёт твоих ответов». Есть «Пока не знаю» — «Стоит понаблюдать». Все связанные ответы A — знакомая привычка, на которую можно опереться. Все C — тема небольшого шага. Другие сочетания — «Зависит от ситуации». Размеры, расстояния и линии компаса не выражают оценку; финансового рейтинга и псевдоточных чисел нет.

Вопросы и связки — редакционный инструмент самонаблюдения, не валидированный тест финансовой грамотности. Нет прогнозов дохода, оценки долгов, склонности к инвестиционному риску или индивидуальных инвестиционных рекомендаций. Общие темы проверки условий и эмоциональных покупок сверены с образовательными материалами проекта Банка России: https://fincult.info/upload/iblock/5ea/ntpgbamnhjqsy0w32o3ptkg2ho1g3u8l/present_ya_i_moi_dengi.pdf. Этот источник не подтверждает связь Big Five с финансовым поведением и не используется для такой связи.

## Сохранение и приватность

Запись требует сессии, владения результатом и доступа к главе. PUT проверяет origin, JSON, размер тела 128 KiB, диапазон ревизии и строгую структуру данных. Массивы имеют фиксированную длину; заметки и итог ограничены 2000 символами, памятка — 8000. Прогресс нельзя записать до начала эксперимента. Неизвестная версия сохранённых данных не перезаписывается.

Ответы API получают `Cache-Control: private, no-store`. Маршрут закрыт от индексации. Текст пользователя выводится средствами React. Данные не добавлены в Метрику, не отправляются в AI и не попадают в старые отчёты. Удаление аккаунта уносит черновик через прежний каскад результатов.

Неактуальная ревизия возвращает 409. Пользователь может скачать локальный черновик и явно загрузить серверную версию. Потеря сети не подтверждается как сохранение. Временное восстановление использует `sessionStorage` этой вкладки; оно зависит от доступности хранилища браузера. После подтверждённого серверного сохранения повторный вход работает и без временного хранилища.

## Подготовка к выпуску

Новый флаг `MONEY_PRACTICE_V1=1` включает маршрут, API и ссылку. По умолчанию флаг выключен: новые таблицы не запрашиваются, прежняя глава работает как раньше. `PERSONALITY_ATLAS_V2` независим.

Перед публикацией: резервная копия БД, миграция `0015_practice_drafts`, проверка восстановленной копии и старых владельцев на внешнем staging, затем явное согласование выпуска. Миграция только добавляет таблицу, внешний ключ, ограничения и индекс. Для отключения достаточно убрать новый флаг; старые данные и таблица прогресса остаются. Не откатывать миграцию удалением таблицы с пользовательскими записями.

Новая миграция проверена на свежей БД со схемой 14 и старыми покупками, отчётами и атласом: сравниваются строки до/после, сохраняется прогресс практикума, восстанавливаются резервные копии до/после. Это локальная проверка, не запуск на производственной БД.

## Команды проверки

`pnpm typecheck`, `pnpm test -- --maxWorkers=2`, `pnpm --filter @grani/web build`.

Браузерные сценарии: `pnpm exec playwright test -c e2e/money-practice.config.ts`. Требуют отдельную базу только на `127.0.0.1:5451` и переменные `MONEY_QA_DATABASE_URL`, `MONEY_QA_SESSION_SECRET`, `MONEY_QA_BASE_URL`, необязательно `MONEY_QA_OUTPUT`. Fixtures создают только синтетические аккаунты. В production-режиме локальных копий используется подписанная тестовая сессия, а не dev-вход.

Скриншоты и итоговый отчёт находятся в рабочем проекте `outputs/money-practice/`. Файлы локальных сессий не входят в коммит.

Не проверены: внешние OAuth и реальная ЮKassa, Safari/iOS, экранный диктор, удалённый staging, производственная БД. Продакшен не опубликован.

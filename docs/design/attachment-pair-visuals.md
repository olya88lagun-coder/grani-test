# ТЗ для Codex: визуал режима пары в тесте на тип привязанности

Дата: 2026-11-08. Логика и тексты уже на сайте (PR #188, #189). Сейчас у новых страниц только базовая вёрстка на существующих классах. Задача — оформить их так же стильно и красиво, как остальной сайт, в общем стиле «Граней».

## Что должно получиться

Новые страницы выглядят как часть сайта, а не как черновик:
- первый взгляд — «это красиво», как на `/privyazannost` и в результате темперамента;
- человеку понятно, что делать дальше: позвать партнёра, принять приглашение, открыть разбор;
- на телефоне (375 px) всё читается и нажимается одним пальцем, без горизонтальной прокрутки.

## Стиль: на что опираться

- `docs/design/visual-direction.md` — общая система. Режим пары — палитра C «Глина» (`data-palette="pair"`), шрифты Cormorant Garamond (заголовки) и Golos Text (текст), скругления `--radius`, плоские панели без теней.
- `/privyazannost` — первый экран теста (ваш дизайн из PR #180, `ShortTestPage`).
- Результат темперамента (ваш PR #187): иллюстрированная карта `AxisMap` с `texture`, `facetedResult`, тёмная полоса `data-band="night"`.
- Страница пары Big Five `/pair/[id]` и приглашение `/p/[token]` (камни `GemPortrait`, «нить» между ними) — образец того, как сайт показывает двоих.

Новых цветов и шрифтов не вводить. Можно добавить иллюстрации в `apps/web/public/attachment/` (webp, как у темперамента).

## Страницы и что в них оформить

### 1. Результат теста на `/privyazannost` — блок «Пройти вдвоём»

Файл: `apps/web/src/components/short-tests/ShortTestResult.tsx`.

Сейчас под результатом три одинаковые по весу кнопки подряд: «Открыть личный разбор — 199 ₽», «Пройти вдвоём с партнёром», «Подробнее о своём типе». Нужно:
- выделить два предложения — личный разбор и «вдвоём» — как две понятные карточки или один блок с двумя вариантами, а не стопку кнопок;
- у «вдвоём» показать, что карта пары бесплатная: превью карты с двумя точками или два камня, текст `pairOffer.lead`;
- остальные ссылки («Подробнее о своём типе», Big Five, «Пройти заново») — второстепенные.

Есть режим `partnerInvite`: результат партнёра, пришедшего по приглашению. Там одна главная кнопка «Увидеть общую карту» и подпись про вход через VK.

### 2. Приглашение партнёра `/sp/[token]`

Файл: `apps/web/src/app/sp/[token]/page.tsx` и `AcceptShortPairForm.tsx`.

Состояния: `not_found`, `used`, `own`, `needs_result` (тест прямо на странице), `ready` (галочка согласия и кнопка «Открыть общую карту»).
- Первый экран для приглашённого — тёплый, личный: «{Имя} зовёт вас пройти тест на тип привязанности вдвоём», образ пары (как камни на `/p/[token]`), короткое «что будет»: 30 утверждений, 5 минут, свой результат сразу, общая карта после согласия.
- Тест (`ShortTestRunner`) должен выглядеть так же, как на `/privyazannost`.
- Состояние `ready`: согласие — заметная, спокойная карточка, не мелкий чекбокс внизу.
- Состояния ошибок — аккуратные, с одной понятной кнопкой.

### 3. Сохранённый результат `/short/[id]` — блок приглашения

Файлы: `apps/web/src/components/short-tests/ShortPairInvite.tsx`, `apps/web/src/app/short/[id]/page.tsx`.

Блок с якорем `#pair`: заголовок, пояснение, кнопка «Получить ссылку для партнёра», потом поле со ссылкой и кнопки «Отправить ссылку» / «Скопировать» (компонент `InviteLink`, общий с другими приглашениями сайта). Ниже — список уже собранных пар («Карта пары: вы и {Имя}»). Сделать блок заметным: после входа человек попадает именно сюда.

### 4. Карта пары `/short-pair/[id]` — главная новая страница

Файл: `apps/web/src/app/short-pair/[id]/page.tsx`. Сейчас это голый список.

Содержимое:
1. H1 «Карта пары: {название сочетания}» (например, «Погоня и побег»).
2. Карта `AxisMap` с двумя точками (`points`) — «Вы» и имя партнёра. Сделать её красивой: иллюстрированная подложка, как у темперамента (`texture`), две точки разных оттенков, подписи не налезают друг на друга, даже если точки рядом.
3. Типы обоих («Вы: …», «{Имя}: …») и одна фраза о динамике — как подпись к карте, а не список.
4. Ссылка «Все сочетания типов в паре».
5. Предложение разбора пары: заголовок, 7 пунктов превью, кнопка «Открыть обоим за 349 ₽» (или «за 249 ₽ — скидка за личный разбор»). Оформить как платную карточку сайта (ср. `/short/[id]` и `/pricing`).
6. После оплаты вместо предложения — сам разбор (`ShortTestReport`): длинный текст из 8 разделов и 3–4 упражнений. Нужна удобная типографика для чтения: ширина строки, отступы, выделение упражнений.
7. «Выйти из пары» — внизу, второстепенная, без тревожного вида.

### 5. Страница сочетаний `/privyazannost/sochetaniya` (открыта для поиска)

Файл: `apps/web/src/app/privyazannost/sochetaniya/page.tsx`.

Сейчас каждый из 10 разделов — заголовок, жирная фраза и один длинный абзац. Нужно:
- первый экран в стиле `/privyazannost` (крошки, H1, короткое вступление);
- 10 сочетаний — карточки или разделы с понятной навигацией: например, сетка 4×4 типов или оглавление с якорями `#secure+anxious` и т. п. (якоря уже есть, на них ведёт ссылка с карты пары);
- длинный текст разбить визуально, не меняя слов: фраза-подзаголовок, абзац, воздух;
- внизу — FAQ (`details`) и кнопка «Пройти тест на тип привязанности».

### 6. Карточка на `/pricing`

Секция `aria-labelledby="price-attachment-pair"` уже в стиле соседних карточек. Проверить, что она смотрится в общем ряду, при необходимости выровнять.

## Ограничения

- **Тексты не менять** без согласования: формулировки вычитаны и частично юридические (согласие партнёра связано с версией `SHORT_PAIR_CONSENT_VERSION`). Можно менять разметку, порядок блоков и вид.
- **Не трогать логику**: маршруты, сервисы, состав данных на странице, кто что видит.
- Тексты платного разбора приходят только с сервера. Не импортировать `@grani/content/short-tests/report` в клиентские компоненты (`"use client"`) — иначе платные тексты уйдут в браузер. Это проверяет e2e.
- Серверные страницы не могут вызывать функции из файлов с `"use client"`. Общие помощники держать в `apps/web/src/lib/` (так уже сделано с `quadrantLabels`).
- Доступность: один H1, правильный порядок заголовков, видимый фокус, контраст по `visual-direction.md`, у карты осмысленный `aria-label` (уже собирается в `AxisMap`).

### Что ищут тесты — сохранить

e2e (`e2e/short-test-attachment-pair.spec.ts`, `short-test-attachment*.spec.ts`) находят элементы по ролям и текстам. Если что-то из этого меняется, обновите тесты в том же PR:
- `data-testid="short-result"` и `data-testid="short-report"`;
- кнопки: «Пройти вдвоём с партнёром», «Увидеть общую карту», «Получить ссылку для партнёра», «Открыть общую карту», «Открыть обоим за 349…» / «…249…», «Выйти из пары», «Открыть личный разбор — 199 ₽»;
- поле с подписью «Ссылка-приглашение», галочка согласия (`role="checkbox"`), поле «Почта для чека»;
- H1 «{Имя} зовёт вас пройти тест на тип привязанности вдвоём», «Это ваша ссылка», «Карта пары: …», «Сочетания типов привязанности в паре»;
- на странице сочетаний ровно 12 заголовков H2 (Кратко, 10 сочетаний, Вопросы и ответы) и H2 с текстом «погоня и побег»;
- на `/pricing` регион «Разбор пары по типу привязанности» содержит 349 и 249.

## Как посмотреть локально

```bash
pnpm dev:db
```

```bash
pnpm dev:web
```

```bash
pnpm dev:worker
```

Нужен `apps/web/.env.development.local` (копия `.env.development.example`: `DEV_LOGIN=1`, `PAYMENTS_FAKE=1`). Пара из двух людей:
1. В обычном окне пройти тест на `/privyazannost` → «Пройти вдвоём с партнёром» → вход через `/api/dev/login?name=Аня` → «Получить ссылку для партнёра».
2. В окне инкогнито открыть ссылку, пройти тест → «Увидеть общую карту» → `/api/dev/login?name=Борис` → галочка → «Открыть общую карту».
3. Оплата разбора — тестовая страница `/dev/pay/…`, кнопка «Оплатить».

Готовый сценарий целиком — в `e2e/short-test-attachment-pair.spec.ts`.

# Первая награда: «Наши способы заботы»
Цель: полезная карточка предпочтений и одного совместного ритуала. Это не психологический профиль и не оценка отношений.
Макет: rewards/care-card-preview.html; вымышленный пример: rewards/care-card-example.json.
Чистая функция сборки: rewards/care-card-engine.mjs. Функция не выполняет авторизацию, не подтверждает платёж и не генерирует PDF.

## Пять пунктов полной версии
1. Первый участник: выбранное действие внимания.
2. Второй участник: выбранное действие внимания.
3. Первый участник: что облегчает обычный день.
4. Второй участник: что облегчает обычный день.
5. Один общий ритуал, подтверждённый обоими.
В подписи показывается автор предпочтения; не переименовывать это в обязанность другого человека. Имя/псевдоним используется без автоматического склонения.

## Источники
attention: m01-d01, m01-d02, m01-d08, m01-d12.
ease: m01-d05, m01-d10, m01-d15, m01-d18.
ritual proposals: m01-d20; общий итог m01-d28 или m01-date04.
Финальный выбор: m01-d27. Сам по себе текст answer не извлекается нейросетью.
Используется отдельная care_action + необязательный care_context с явным allow_care_reward. Участник может изменить/удалить кандидат. Выбор доступен после раскрытия ответа.
Новый пункт можно вручную добавить в итоговой форме от собственного имени; это отдельный источник month01-wrap, а не выдумка алгоритма.

## Алгоритм
1. Backend проверяет членство, право на результат первого оплаченного этапа, видимость и актуальные версии материалов.
2. Собирает только разрешённых кандидатов для конкретного пространства.
3. Каждый выбирает свой attention и ease; можно пропустить.
4. Для ритуала оба подтверждают один финальный вариант и его версию.
5. buildCareCard строит список из реально выбранных пунктов. Если кандидата нет/нет согласия, слот отмечается missing, текст не выдумывается.
6. Пара просматривает карточку. Для совместного экспорта оба одобряют один snapshot.
7. Экспорт создаётся автоматически и остаётся доступен после отмены продления по общим правилам личных файлов.

Если материалов мало: право на награду уже заработано. Показать короткий вариант и добровольное дополнение, не требовать завершить 28 карточек. Полный вариант из пяти пунктов — предпочтение, не блокировка.
Пустой вариант: готовый макет и нейтральное приглашение добавить один собственный пункт. Не утверждать, что алгоритм «узнал пару».

## Короткое добровольное дополнение
Первый и второй участники независимо:
- Какое небольшое действие помогает вам почувствовать внимание?
- Что из посильной помощи облегчило бы ваш обычный день?
Пара:
- Какое простое совместное действие хочется иногда повторять?
- Когда и сколько времени подходит обоим?
Каждое поле можно пропустить. Пара решает, что оставить.

## Время
Предварительная мини-карточка может появиться после первой недели. Итоговое право — по завершении первого оплаченного этапа.
Посещения и количество карточек не являются условием права. Не путать число платежей с завершёнными предоставленными этапами.
Перерывы/возвраты/право после отмены должны использовать единый entitlement service, не логику preview.

## Версии и согласия
Выбор/исправление/имена/контекст/ритуал изменяют hash карточки и сбрасывают прежние одобрения. Оплата и участие в программе не являются согласием на конкретный экспорт.
Функция получает разрешённый server snapshot; не доверять присланным клиентом allowReward, ownerId, confirmedBy или selections.
Чужие/неверные категории отклоняются. Функция допускает отсутствие пунктов. В preview для простоты показан только полный вымышленный вариант.
Не отправлять текст карточки в рекламную аналитику.

## Оформление
Кремовый фон, сливовый заголовок, пять плоских блоков. Первые четыре в два столбца на компьютере и один на телефоне; общий ритуал — на всю ширину. Небольшие подписи контекста, без оценок и баллов. Печать/скачивание — после согласования.
Пример можно редактировать. При редактировании preview сбрасывает оба checkbox одобрения; печать блокируется до новых отметок. Это демонстрация интерфейса, не два реальных аккаунта.

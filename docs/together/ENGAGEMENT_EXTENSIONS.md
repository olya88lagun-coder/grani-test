# Вдвоём — четыре дополнительных формата · v6
Дата: 2026-10-03. Пользователь утвердил добавление всех четырёх идей.
Статус: концепция и сценарии для Claude. Рабочие функции, новые макеты, полный контент и проверки пока не созданы.
Связанные материалы: [ENGAGEMENT.md](./ENGAGEMENT.md), [SPEC.md](./SPEC.md), [EDGE_CASES.md](./EDGE_CASES.md), [CLAUDE_HANDOFF.md](./CLAUDE_HANDOFF.md).

## Место в продукте
В общую программу входят шесть новых форматов: «Угадай меня», «Свидание из конверта» и четыре ниже. Все четыре ниже утверждены, а не отложены как нерассмотренные идеи.
На главной достаточно одной актуальной карточки и входа «Для нас»; там игры, свидания, желания, традиции и письма. Не превращать домашний экран в шесть конкурирующих обязательных заданий.
Форматы доступны добровольно. Еженедельные игры/конверты — предложение ритма; желания, письма и традиции открываются по инициативе пары.
Одна оплата за двоих, 599 ₽/30 дней — прежняя рабочая гипотеза. Внутри программы нет отдельных доплат за открытие письма или общих желаний.
AI для этих четырёх форматов не нужен: готовые идеи, явные настройки и материалы участников.
Добавление в концепцию расширяет объём разработки; его нужно оценить отдельно. Годовая карта и M1–M3 прежней программы сохраняются. Ранее выполненная QA относится к прежним макетам.

## 1. Маленький сюрприз
Ценность: партнёр проявляет заботу в обычной жизни; сервис помогает придумать действие.
Крючок: «Выбери, чем порадовать своего человека».

### Сценарий
1. Каждый добровольно отмечает комфортные категории: слова, помощь, совместное время, необязательный небольшой подарок. Общие категории не являются психологическим «типом».
2. Для подбора каждый задаёт допустимые бюджет/время и ограничения. По умолчанию — без обязательных покупок.
3. Инициатор видит подходящие подготовленные идеи и выбирает одну, заменяет её или отказывается.
4. Платформа не уведомляет получателя о выборе до желания инициатора; по умолчанию сюрприз происходит вне сайта.
5. Инициатор может сам сообщить партнёру через сервис, если тот согласился получать такие сообщения. Текст и имя отправителя показываются инициатору до отправки; сервис не сочиняет признания от чужого имени.
6. Получатель может сохранить собственное впечатление в личном черновике. Это необязательно; отметка «спасибо» не требуется.
7. Нет оценок исполнения, напоминаний от имени обиженного партнёра или счётчика «кто сделал больше».

### Готовый редакционный пример
ID surprise-note-01, version 1, editorial-draft.
Категория: тёплые слова. До 5 минут, без покупок; подходит дома и на расстоянии.
«Напиши две короткие фразы: какое небольшое действие партнёра недавно тебя порадовало и почему. Оставь записку или отправь сам в привычном чате».
Подсказка: «Мне было приятно, когда ты ____. Для меня это ____».
Ничего не отправляется автоматически; слова остаются словами автора.
Альтернатива: сказать лично. Можно пропустить.

### Данные и состояния
Собственные настройки → доступная идея → личный выбор/черновик → действие по желанию → личное впечатление.
Личный черновик и выбранный, ещё не сообщённый сюрприз доступны только автору. Получатель не видит список вариантов автора.
Физические подарки/покупки/доставка не входят в тариф; автор организует их самостоятельно, если выбирает такой сценарий.

## 2. Нам обоим хочется
Ценность: находить совместные занятия без необходимости угадывать интерес другого.
Крючок: «Узнайте, какое желание у вас совпало».

### Сценарий
1. Каждый выбирает из подготовленного каталога занятий. Свободный текст можно сохранить лично; автоматического смыслового сопоставления текста в первой версии нет.
2. Для каждой выбранной идеи есть отдельное разрешение «Показать, если партнёр тоже выберет». По умолчанию личные записи не раскрываются.
3. Совпадение показывается только если оба выбрали один стабильный ID идеи и оба разрешили раскрытие.
4. Сервер возвращает общие совпадения и собственный список; чужие невзаимные выборы, количество скрытых желаний и отказы не возвращаются клиенту.
5. При пустом результате: «Пока нет открытых совпадений. Можно выбрать другие идеи или придумать занятие вместе». Это не оценка отношений.
6. Из совпадения можно предложить план. Дата/место/расходы считаются согласованными только после двух подтверждений.
7. Совпадение не означает согласие на действие, расходы или физическую близость.

### Готовый редакционный пример
ID wish-new-breakfast-01, version 1, editorial-draft.
«Позавтракать вместе в необычном для нас месте».
Варианты: дома с новым блюдом, на прогулке, в выбранном кафе; бюджет согласуется отдельно.
После разрешённого совпадения: «Вам обоим хочется необычного завтрака. Выбрать вариант?»
Альтернатива без покупок: сменить привычное место завтрака дома и добавить каждый по одной приятной детали.
Оба выбирают подходящий вариант и подтверждают время; без двух подтверждений это лишь предложение.

### Приватность и обновления
Подбор только по фиксированным ID, без AI, рейтинга совместимости или публикации списков.
Отзыв разрешения убирает идею из текущих совпадений и отменяет ожидающее раскрытие; уже прочитанное другим человеком технически нельзя стереть из памяти.
Добавление/отмена/восстановление одного желания не создаёт новых одинаковых уведомлений. Чужие изменения в личном списке не анонсируются.
Для совместного плана — отдельные ревизия и два подтверждения; изменения условий сбрасывают подтверждения.
Проверить риск перебора: только обычный каталог, без произвольных запросов «выбрал ли партнёр X», без поиска его личных текстов. Не предлагать чувствительные темы в начальном каталоге.

## 3. Открыть позже
Ценность: личное письмо к значимой дате; развитие годовой капсулы времени уже с начала участия.
Крючок: «Оставьте друг другу письмо, которое откроется в выбранный день».

### Сценарий
1. Автор выбирает адресата — действующего подтверждённого партнёра — и дату/время открытия с явно показанным часовым поясом.
2. Пишет письмо, видит предварительный просмотр и выбирает «Сохранить черновик» или «Запланировать открытие».
3. До открытия текст видит только автор. Уведомление адресату о наличии запланированного письма — отдельное добровольное действие; текст письма в него не включается.
4. До открытия автор может редактировать, перенести дату или удалить письмо. Повторное планирование заменяет прежнюю задачу.
5. В назначенный момент сервер проверяет актуальную версию, отправку/отзыв автора и действующее членство обоих. Только затем делает письмо доступным адресату.
6. После открытия адресат получает нейтральное уведомление «Для вас открылось письмо» по собственным настройкам. Открытие права чтения не равно гарантированной доставке/прочтению.
7. Открытый текст сохраняется конкретной версией; тихое изменение уже доставленного письма запрещено. Дополнение — отдельное сообщение.
8. Ни автор, ни сервис не требуют ответа или благодарности.

### Готовый редакционный пример
ID letter-next-chapter-01, version 1, editorial-draft.
Тема: «Что мне хочется сохранить о нас».
Подсказки: «Мне особенно дорог момент ____. Спасибо тебе за ____. В ближайшие месяцы мне хочется вместе ____».
Каждый пункт можно пропустить, полностью переписать или оставить письмо личным черновиком.
Получатель выбран заранее; письмо не превращается в совместно написанный текст.

### Доступ, отмена и выход
Обычная отмена продления/истечение оплаченного срока не требует новой оплаты для открытия уже запланированного письма. Оно может открыться, пока оба остаются участниками, согласия действуют и данные не удалены.
Создание новых писем после окончания доступа — по общим условиям тарифа; ранее сохранённые черновики/письма не удалять автоматически.
Выход любого участника, удаление данных или отзыв отправки блокируют будущую доставку; задачи отменяются на сервере. Новому партнёру старые письма не переносятся.
Право на чтение уже открытых писем после выхода/удаления — по EDGE_CASES.md и отдельным правилам хранения; не обещать вечное хранение.
Не отправлять письмо вложением/текстом в сторонний мессенджер. На сайте — проверка адресата и членства. Уже вручную сохранённое/скопированное адресатом технически нельзя отозвать.
Письмо не включается в книгу автоматически: нужны явный авторский выбор, разрешённый source mapping и одобрение обоими точного снимка книги.

## 4. Наши маленькие традиции
Ценность: превращать понравившееся занятие в личный повторяемый ритуал.
Крючок: «Создайте то, что будет только вашим».
Развитие существующей карточки заботы; не создавать вторую независимую копию тех же договорённостей.

### Сценарий
1. Один предлагает готовую или собственную традицию: название, короткое описание, удобный ритм.
2. Второй подтверждает или предлагает изменение. До двух подтверждений — личное предложение, не «мы договорились».
3. Оба выбирают, нужны ли напоминания; каждый управляет собственными временем и каналом.
4. После занятия каждый может добавить личное воспоминание. Фото в первой версии не обязательно; загрузка требует отдельной реализации storage/согласий.
5. Традицию можно поменять, поставить на паузу или завершить. Общие изменения вновь подтверждают оба.
6. Любой может прекратить своё участие и собственные напоминания сразу, без разрешения другого.
7. Нет обязательных серий, штрафов, долга за пропуски, оценок отношений или сравнения усилий.

### Готовый редакционный пример
ID ritual-sunday-breakfast-01, version 1, editorial-draft.
Название: «Наш медленный завтрак».
«В выбранный выходной выделить 15 минут на завтрак без обсуждения дел. Каждый может назвать один приятный момент недели».
Ритм — выбирают оба; напоминание необязательно. Нет требований к еде и покупкам.
Альтернатива на расстоянии: короткий созвон за привычным завтраком.
Сохранение воспоминания: добровольная личная заметка; её отсутствие не означает, что традиция не состоялась.

### История и книга
Разрешённые личные заметки могут перейти в книгу только после выбора автора и двух одобрений снимка.
Подтверждённая традиция может стать joint source после явного расширения BOOK_MAPPING; обычное предложение не превращается в факт о паре.
Повтор традиции — намеренно повторяемый ритуал, а не ошибка неповторяющегося каталога программы.
Пауза напоминаний не замораживает оплаченные дни. После окончания доступа новые служебные напоминания о регулярной традиции выключены; сохранённая история обрабатывается по общей политике.

## Порядок реализации всех утверждённых форматов
1. Безопасное пространство двух аккаунтов, вопрос/ответ/раскрытие и один реальный добровольный канал уведомлений.
2. «Угадай меня» и конверты — демонстрация на первом знакомстве и еженедельный повод вернуться.
3. Сюрпризы и общие желания — действия в обычной жизни; затем подтверждённые общие планы.
4. Традиции и отложенные письма — долговременная история с проверенной отменой/доступом/фоновыми задачами.
Все четыре дополнительных формата входят в утверждённый объём продукта. Последовательность нужна для разработки; маркетинг обещает лишь то, что фактически доступно в выпущенной версии.
Новые экраны и полный каталог каждого формата подготовить и проверить отдельно. Не заявлять, что прежний автономный макет уже содержит эти возможности.

## Технические границы и приёмка для Claude
- Авторизация/права/версии/согласия проверяются на сервере, не флагами демо.
- Личные черновики сюрприза, невзаимные желания и неоткрытые письма не попадают в payload второго участника, сторонний лог или рекламную аналитику.
- Два одинаковых разрешённых выбора открывают одно совпадение; отзыв разрешения убирает его без ложного нового события.
- Условия совместного плана/традиции требуют двух подтверждений конкретной версии. Отказ или остановка личного участия не блокируются вторым участником.
- Письмо: разные часовые пояса, редактирование/перенос/удаление до даты, повторная обработка, обычная отмена подписки, выход участника до открытия, отзыв во время выполнения задачи.
- Доставка фоновых событий идемпотентна; устаревшие задачи не отправляют старый текст/повторное уведомление. Текст письма никогда не входит в наружное уведомление.
- В первой версии не нужны внешняя AI-генерация, push всех платформ одновременно, фотографии или интеграция с доставкой подарков.
- На телефоне карточка формата открывается прямо из уведомления; вход возвращает к ней, проверяя текущее членство.
- Пустые состояния: нет настроек сюрприза, нет общего желания, письмо-черновик/ожидание/открыто/отозвано, традиция-предложение/активна/пауза/завершена.
- Проверить 320/390/768/1440, клавиатуру, длинный русский текст, отключённые уведомления, два независимых аккаунта.
- В аналитике только тип действия и ID каталога, без личного содержания. Отметка «сделано» не доказывает действие в жизни.
- Пилот проверяет удобство, добровольное участие обоих, реальные совместные действия, возвращение и фактическое продление. Польза и рост удержания пока не доказаны.

## Визуальное решение

Палитра «Глина», шрифты Cormorant/Golos, поверхности без тяжёлых теней. Стили используют действующие токены сайта. CSS Module защищает тест личности, главную страницу, результаты и старые карточки от изменения оформления.

На телефоне основные поля имеют 16 px, действия не менее 44 px по высоте. На широком экране пилот расположен в двух колонках; способы заботы двух авторов — в отдельных светлых панелях. При длинных именах и непрерывных строках содержимое переносится. Учтены клавиатура, видимый фокус и prefers-reduced-motion.

## 1. Закрытый пилот и форма кода

Левая часть коротко объясняет вход по приглашению. Правая содержит вход через VK ID или код, в зависимости от signedIn. Цена, витрина и обещания программы здесь отсутствуют.

Форма кода:
- Подпись и подсказка, placeholder без настоящего кода; прежний лимит 64 символа.
- Пустой код не отправляется; при проверке поле и кнопка недоступны.
- Ошибка связана с полем через aria-describedby. Только invalid_code ставит aria-invalid; сеть или отсутствие мест не объявляются ошибкой ввода.
- При изменении текста старая ошибка снимается. Успех по-прежнему перезагружает страницу; 401 использует существующий вход.
- Сохранены POST /api/together/pilot { code }, тексты pilotCodeFailure и серверные ограничения попыток.

Не показывать клиенту настоящие pilot code, лимит или данные участников. Не менять правила выдачи пропусков через приглашение.

## 2. Записка и первый вопрос

У инициатора форма выглядит как короткое личное приглашение: заголовок, поле на светлой бумаге, счётчик из 200, отдельное сохранение.

Поле остаётся управляемым TogetherSpace. maxLength передаётся из TOGETHER_INVITE_NOTE_MAX, не создаёт второй лимит. Пока идёт сохранение, поле недоступно. Текст не отправляется при каждом вводе.

Содержимое прежней записки после обновления не приходит в SpaceView. Поэтому подсказка прямо объясняет: пустое поле не означает, что старой записки нет в приглашении. Новый текст заменяется только после «Сохранить записку».

Когда поле пустое или содержит только пробелы, действие подписано «Убрать записку» и поясняет, что сохранение удалит прежний текст. Запрос остаётся PUT /api/together/invite/note { note }; успешные сообщения и ошибки остаются у TogetherSpace. API получения старой записки не добавлялся.

На странице принимающего:
- Имя и записка появляются только из валидного серверного preview.
- Записка оформлена как отдельное письмо; сохраняются переносы, React экранирует текст.
- Первый вопрос читается без входа. Полей для ответа и скрытых ответов здесь нет.
- При отсутствии записки нет пустого «письма» или фиктивного текста.
- Не изменены текущий GET проверки ссылки { valid }, срок ссылки, noindex/nofollow, no-referrer, проверка режима и запрос участия.

## 3. Ссылка для друзей

Закрытый по умолчанию блок сохраняет native details/summary. В заголовке — «Поделиться с парой друзей», подпись и небольшой знак, на который не возложен смысл.

Внутри пояснение о самостоятельном пространстве друзей и приватности материалов. Ссылка запрашивается только кнопкой «Получить ссылку», а не автоматически при открытии блока.

После успешного POST /api/together/share { }:
- Read-only поле со ссылкой.
- «Скопировать ссылку».
- Сообщение только после завершённого clipboard.writeText.
- При отказе clipboard выделяется поле, появляется инструкция ручного копирования.
- При ошибке запрос можно повторить; фиктивная ссылка не появляется.

Код, скидки, награды и доступ пилота не добавляются этим интерфейсом. Правила атрибуции и cookie не менялись. Ссылка из автономного просмотра исключительно вымышленная.

## 4. Итог месяца «Наши способы заботы»

Блок по-прежнему появляется только по успешному GET /api/together/care с ready: true и card. Клиент не вычисляет готовность по номеру карточки, количеству ответов или оплаченным дням.

Оформление:
- Заголовок итога и короткое объяснение личного выбора.
- Отдельная панель каждого автора.
- Разделы «Как мне показать внимание» и «Что делает мой день легче».
- Контекст отдельной строкой, без повторного добавления «Когда:» к пользовательскому тексту.
- Идеи ритуала идут отдельным блоком под именами предложивших. Их не объявляют подтверждённым общим соглашением.
- Если у одного автора нет выбранных пунктов, показана ясная подпись.
- Если card.empty, отдельное пустое состояние без вымышленных советов и заполненных примеров.
- Неполная карточка не требует обязательного заполнения всех разделов.

Удалена прежняя инструкция «открыть свои ответы в истории и отметить»: история сейчас не даёт такого редактора. Кнопки скачивания, согласования общего ритуала или ИИ-обработки не добавлены. Пункты, авторство, complete/empty и контекст поступают из существующего API. Ключи списка допускают одинаковые тексты без предупреждений React.

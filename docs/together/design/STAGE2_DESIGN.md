## Визуальная система и расположение

Сохранён стиль «Глина»: фон #FFFCFA, поверхность #F6E8E1, сливовый акцент #4A2230, основной текст #2A2224. Заголовки Cormorant Garamond 300, интерфейс Golos Text 400/600. Радиусы 14 px, тонкие границы, без тяжёлых теней.

На широком экране слева карточка, справа прогресс и история. На телефоне карточка на всю ширину, краткий done/total виден над ней, подробный блок прогресса и ссылка на историю ниже. Раскрытые ответы стоят рядом на большом экране и последовательно на телефоне. Не обрезать длинный текст; переносить непрерывные строки и длинные имена.

Порядок раскрытия: вопрос; собственный ответ и личный выбор для книги; ответ партнёра; маленький шаг; необязательная отметка «Сделали вместе»; «Продолжить».

## 1. Ответ — answer

Показать:
- Этап и position, название, вопрос, подсказку, estimatedMinutes.
- Поле answer, required и maxLength из снимка.
- Все дополнительные short_text из fields. Например, care_action до 180 символов и care_context до 100. Необязательные поля явно подписать.
- Статус партнёра только из partner.status. При answered текст остаётся скрытым.
- Текст: «Ответы откроются, когда ответят оба. До этого партнёр видит только статус».
- «Отправить ответ» и «Пропустить карточку», если нет locked.

PUT /api/together/cards/[id]/answer: { fields }. До раскрытия разрешённые текстовые поля сериализуются по снимку; все availableAt: "after_reveal" полностью отсутствуют в теле. Не отправлять share_in_book: false, allow_care_reward: false или defaults всей формы.

Пример первой отправки:
```json
{"fields":{"answer":"Мне нужны пять минут тишины.","care_action":"Обними меня после небольшой паузы.","care_context":"После работы."}}
```

Защитить форму от двойного клика. Ошибка не удаляет текст и не переводит в waiting. Проверить пустоту, ограничения длины и недопустимые символы; окончательное решение принимает сервер.

Если PUT вернул waiting — показать сохранённый собственный ответ. Если revealed — немедленно показать результат этой же карточки, не следующую.

## 2. Ожидание — waiting

Заголовок: «Ваш ответ на месте». Пояснение: «Когда партнёр ответит, здесь откроются оба ответа. Можно вернуться позже».

Показать собственный отправленный ответ. Доступны «Изменить ответ», «Удалить ответ», «Проверить ответы», «Пропустить карточку». Кнопки «Продолжить» и полей для книги здесь нет.

- Правка до раскрытия — повторный PUT по текущей карточке без after_reveal-полей.
- Удаление — диалог «Удалить свой ответ?»; после подтверждения DELETE /answer и повторное чтение current.
- «Проверить ответы» — GET current. Прототип проверяет только вымышленное состояние.
- При реальном подключении обновлять при возвращении фокуса/видимости страницы; ограниченный polling запускать только в waiting и останавливать на скрытой вкладке, результате, выходе и размонтировании. Не обещать уведомления: они не входят в этап 2.
- Если раскрытие произошло во время редактирования, сохранить локальный несохранённый текст, перечитать карточку и явно показать новый статус. Не выбрасывать изменения из формы.
- При появлении revealed/skipped оставаться на данном результате.

До раскрытия не загружать ответы партнёра «для последующего показа», не прятать их только CSS. Фикстуры прототипа находятся в памяти страницы и не доказывают защищённость реального сервера.

## 3. Раскрытие — revealed

Две панели «Ваш ответ» и имя партнёра. Показывать основное и заполненные дополнительные текстовые поля с label из снимка. На чужой панели нет управления выбором для книги или редактированием.

Отметка «изменено»:
- У партнёра — только по partner.edited.
- У себя — по mine.revision > 1.
- Правка текста после раскрытия делается PUT на прежний id. Сохранять остальные собственные поля.
- Изменение только булевого выбора для книги не увеличивает текстовую ревизию и не создаёт «изменено».
- Удалить раскрытый ответ нельзя: кнопка удаления отсутствует.

После раскрытия у своего ответа появляются boolean-поля availableAt: "after_reveal":
- share_in_book: «Хочу выбрать свой ответ для будущей книги».
- allow_care_reward, когда есть в снимке: «Предлагаю этот пункт для итоговой карточки».

Автосохранение выбора — PUT { fields } с собственным актуальным текстом и собственными флагами. При ошибке откатить галочку к подтверждённому сервером значению и показать сообщение. Не показывать успешное сохранение до ответа сервера. Здесь только выбор материала; книга и награды относятся к следующему этапу.

Блок «Маленький шаг» показывает jointAction и checkbox «Сделали вместе». На текущем контракте checkbox меняет локальное намерение; POST continue отправляется только при нажатии «Продолжить». Так галочка не отмечает итог просмотренным раньше кнопки.

- Обычное продолжение: POST /continue {}.
- Продолжение с отметкой: POST /continue { done: true }.
- mine.done: true — уже сохранённая отметка, галочка отмечена и недоступна для снятия. API не поддерживает отмену done.
- partner.done: true — отдельная подпись о том, что партнёр отметил действие. Не выдавать это за согласие обоих.
- Отметка необязательна и не влияет на доступ к следующей карточке.

Итог остаётся до успешного личного Continue, включая refresh и переход в историю. Продолжение одного человека не убирает итог у второго. Ошибка Continue сохраняет результат на экране; следующая карточка не выбирается оптимистически.

## 4. Пропущено — skipped

Текст: «Карточка пропущена. Карточка закрыта для вас обоих. Ответы друг другу не откроются».

Если mine существует, показать собственный ответ с подписью «Только вам». Не показывать текст партнёра, даже когда partner.status: answered. Если пропустил сам автор, его прежний ответ удалён; не восстанавливать его из локального черновика.

На результате нет редактирования, удаления, выбора для книги и «Сделали вместе». Есть «Продолжить». Пропуск считается в progress.done.

До POST /skip показать подтверждение:
«Пропустить для обоих? Карточка закроется. Ответы не раскроются. Если партнёр уже ответил, его текст останется только у него. Ваш отправленный ответ будет удалён».

### Нюанс собственного пропуска и восстановление после перезагрузки

Сейчас skipCard автоматически ставит seen_at тому, кто пропустил. Поэтому следующий GET current этому человеку уже вернёт следующую карточку. У партнёра skipped остаётся на сервере до Continue.

Макет сохраняет собственную квитанцию пропуска локально и держит её до «Продолжить», включая имитацию refresh. Это не новый серверный state. Полная перезагрузка страницы в статическом макете сбрасывает фикстуры и не проверяет восстановление реальной квитанции.

Для подключения без изменения сервера реализовать восстановление:
1. После подтверждённого POST /skip хранить только { cardId, position } как квитанцию текущего пользователя в sessionStorage. Ответы и имена туда не писать.
2. Перед показом следующего вопроса проверить квитанцию через авторизованную историю: GET /history?before=position+1 и точное совпадение id/outcome. Не доверять одному локальному id.
3. Восстановить результат skipped из ответа истории. Не показывать следующий вопрос, пока восстановление не завершено.
4. После успешного личного Continue удалить квитанцию и перечитать current. При смене аккаунта/выходе/404 удалить квитанцию и все совместные кэши.
5. Если карточка не найдена, очистить устаревшую квитанцию; при сетевой ошибке оставить возможность повторить восстановление.

Если нужен одинаковый серверный сценарий на всех устройствах, изменить skipCard: ставить seen_at только на Continue. Это отдельная согласованная поправка Claude с обновлением серверных тестов. Макет сервер не меняет.

## 5. Оплата и экран после оплаты

При locked: true заголовок вопроса остаётся виден. Вместо формы — «Продолжите вдвоём», стоимость для пары и «Открыть доступ». Нет кнопки пропуска, textarea и галочек.

Текст: «Три вводные карточки доступны бесплатно. Чтобы отвечать на основной маршрут, откройте доступ для пары». Цена макета 599 ₽/30 дней; в приложении брать сумму/период из общей конфигурации этапа 1, без второго источника цены.

Кнопка использует существующий checkout этапа 1. Прототип имитирует только переход к проверке; не создавать новый платёжный протокол.

Возврат платежа сам по себе ничего не разблокирует. Перечитать purchase, space.access и current согласно этапу 1. Только после подтверждённого доступа и current.locked: false показать баннер:
«Доступ открыт для вас двоих. Продолжайте с этой карточки. Ваши вводные ответы сохранены».

position и id остаются прежними. При задержке: «Проверяем оплату», «Не оплачивайте повторно». При 409 access_required карточка не закрывается и не считается пропущенной. Истечение доступа у уже ответившего не должно прятать собственный ответ или раскрытый результат.

## 6. История и прогресс

progress.done — количество закрытых карточек пространства, включая пропуски. Это не количество дней, выполненных действий или личных нажатий Continue. total приходит с сервера; сейчас 29. Не увеличивать счётчик локально при нажатии кнопки.

История: GET /api/together/history. Карточки по убыванию position; показывать title, prompt, outcome. Нажатие открывает диалог чтения. Просмотр истории не вызывает Continue и не теряет ожидающий итог.

- revealed: оба ответа, partner.edited; собственный выбор для книги можно обозначить, если подтверждён в mine.fields.
- skipped: только собственный answer, если есть; чужого текста нет.
- Пустая история: «История ещё впереди. Здесь появятся раскрытые и пропущенные карточки».
- Пагинация: передавать next как before следующего GET, добавлять результаты без дублей. В прототипе вымышленная история из 23 карточек показывает первый набор 20 и затем три.
- card: null — «Вы прошли этот маршрут», ссылка на историю. Число карточек брать из progress.total.

Контракт истории сейчас не гарантирует mine.done, jointAction и поля снимка с label/maxLength. Поэтому в истории нет постоянной отметки «Сделали вместе», повторного редактора или редактируемых галочек. Не выдумывать эти данные и не брать изменившийся каталог вместо снимка. Для этих расширений Claude должен дополнить контракт истории. Текущий макет истории показывает основной текст ответа; дополнительные поля видны в текущем раскрытии.

## 7. Ошибки и доступность

| Ответ API | Поведение |
| --- | --- |
| 400 invalid_field | Ошибка у формы; сохранить локальные поля. Проверить ограничения снимка. |
| 400 field_not_available | Убрать недоступные after_reveal-поля из сериализации, перечитать карточку. Не повторять тот же неправильный payload автоматически. |
| 400 invalid | Показать ошибку действия/параметров; не менять прогресс. |
| 401 | Вернуться во вход через VK ID с returnTo=/together. Не передавать текст ответа в URL. |
| 403 | Обновить страницу/сессию, повторить действие вручную. |
| 404 | Нейтральное «Пространство недоступно», очистить совместные данные и квитанции. Не объяснять, чья карточка или кто вышел. |
| 409 already_closed | Перечитать current, показать реальный раскрытый/пропущенный итог. |
| 409 already_revealed | Обновить revealed; убрать удаление ответа. |
| 409 reveal_pending | Получить current; показать самый ранний непросмотренный итог и Continue. |
| 409 access_required | Показать доступ/оплату, сохранить позицию и локальный текст. |
| 409 skip_not_allowed | Показать запрет; не переходить дальше. |
| 409 not_closed | Получить current и вернуть answer/waiting. |
| 429 | Уважать Retry-After, если есть; остановить частые повторы, сохранить текст. |
| Сеть/5xx | Не показывать успех. Сохранить текущий экран и локальный текст, предложить ручной повтор. |

Автоматические повторы только для безопасных чтений; не выполнять «пропустить», «удалить» или «продолжить» вслед за ошибкой без подтверждения пользователя. UI блокирует повтор во время запроса. Ответы, поля, UUID карточек, имена и invite tokens не отправлять в аналитику/логи.

Форма имеет label, maxlength, required. Диалоги закрываются Escape, возвращают фокус на исходную кнопку и очищают содержимое после закрытия. Минимальная высота кнопок 44 px, поля 16 px на телефоне. Сообщения ошибок role=alert, изменения состояния aria-live. Учтён prefers-reduced-motion. После успешного Continue перенести фокус на заголовок следующего вопроса.

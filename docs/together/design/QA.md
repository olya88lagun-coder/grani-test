## Подтверждено исполнением
72 проверки, включая 55 сочетаний 11 состояний и 5 ширин: 320/390/768/1024/1440.
В каждом сочетании проверены ширина документа и границы реальных элементов. Ошибок JavaScript, 4xx-ответов и внешних запросов на основных экранах нет. Это геометрическая проверка, не доказательство отсутствия любого возможного наложения.
Независимый free CTA → личная ссылка → принимающий → ожидание подтверждения инициатора → подтверждение → пространство → первая встреча.
Два демонстрационных участника, ожидание до второго ответа, раскрытие, выбор только своей записи, безопасный вывод текстовой разметки и перенос длинного слова на320.
PDF закрыт до двух одобрений. Изменение выбранного фрагмента сбрасывает оба. Пустая книга не экспортируется.
Нативный dialog/Escape, мобильное меню, видимый keyboard focus, reduced-motion.
Реальные локальные файлы брендовых Cormorant/Golos загружены. Это не системная подмена шрифтов.
23 JPG-снимка в artifact (22 состояния на390/1440 + диалог карточки заботы); отдельно print-снимок и реальный вымышленный A5 PDF на4 страницы.
Автономный HTML с вшитыми шрифтами открыт через file:// и проверен: без установки проекта отображается страница и работает переход в приглашение.

## Для пользователя
В artifact лежит grani-together-review.html: распаковать ZIP, открыть этот файл в браузере. Все пять экранов и шрифты внутри.
Тот же файл сохранён в [deliverables](./deliverables/grani-together-review.html); GitHub показывает HTML-исходник — для просмотра скачать файл и открыть локально.
Данные вымышлены, до перезагрузки живут только в памяти. Не вводить личные истории.
Демонстрационный PDF — образец печатного оформления, не результат оплаченного продукта и не обещанный объём книги.

## Границы
Серверных аккаунтов, приватного хранения, оплат, настоящих уведомлений, webhook-обработки и серверного PDF здесь нет. UI-проверка не заменяет security acceptance из BOOK_MAPPING/EDGE_CASES.
Browser QA выполнен в GitHub Actions, локальные инструменты Codex недоступны. На grani-test.ru макеты не опубликованы.
Окончательный production-рендер необходимо проверить после переноса в Next.js, включая реальные строки/имена, keyboard order и итоговый PDF.

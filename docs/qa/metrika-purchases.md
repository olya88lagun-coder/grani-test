# Учёт покупок в Яндекс Метрике

## Сопоставление с заказами

`checkout_start` отмечает переход к оплате. Автоцель возврата из платёжной системы фиксирует возврат. Для отчёта о подтверждённых покупках используются цели из таблицы.

Сервер выдаёт данные только плательщику после подтверждения статуса, суммы, валюты и связи платежа с заказом. В событие попадают `order_id` (стабильный непрозрачный ID), `product` (точный тип заказа), `order_price` (сумма из заказа в рублях) и `currency` (`RUB`). Отправка требует согласия на аналитические cookie. Отметка по ID сохраняется до вызова SDK, поэтому обновление и повторное открытие в том же браузере с сохранённым хранилищем не повторяют событие. Если отметку нельзя сохранить, отправка откладывается. Браузерный учёт зависит от доступности SDK и хранилища.

## Приёмка в тестовой среде

1. Укажите отдельный тестовый счётчик в `NEXT_PUBLIC_METRIKA_TEST_ID` при запуске разработки или сборке стенда. Создайте в нём шесть целей типа «JavaScript-событие» с именами из таблицы. Рабочий номер отклоняется настройкой тестового режима.
2. Выполните тестовую оплату. В отладчике Метрики (`_ym_debug=2`) проверьте цель и четыре параметра. Затем проверьте одно достижение в отчёте тестового счётчика.
3. Обновите страницу возврата, вновь откройте её и страницу результата. Убедитесь, что число событий покупки не выросло.
4. Отмените платёж и отдельно проверьте отказ провайдера. Для обоих исходов число событий покупки должно остаться прежним.

Локальный сценарий `e2e/purchase-analytics.spec.ts` использует тестовую оплату и перехватывает вызовы SDK. Он проверяет данные события и отсутствие повторов без записи в Метрику.

## Отдельное включение на рабочем сайте

После согласования создайте три отсутствующие цели в `112931559`. Для «Грани. Вдвоём» дополнительно задайте `METRIKA_TOGETHER_PURCHASES=1` в окружении приложения. Тестовый номер используется только на стенде.

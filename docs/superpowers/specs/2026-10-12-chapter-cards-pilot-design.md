# Пилот: глава «Деньги» в формате карточек

Дата: 2026-10-12. Ветка: `feat/chapter-cards-pilot`. Статус: ждёт проверки владелицей.

## Зачем

Глава за 99 ₽ сейчас — 5 абзацев (≈230 слов) и 5 советов, собранных по очереди по пяти чертам. Читать её тяжело, брать из неё нечего: нет ситуаций, готовых фраз, объяснения «почему так». Инструкция для ИИ ограничивает главу 800–2500 знаков и запрещает «добавлять факты», поэтому модель только пересказывает блоки библиотеки.

Цель пилота — проверить на одной главе формат, за который не жалко 99 ₽: больше информации, но не «полотном»: карточки по 20–30 секунд чтения, у каждой — узнавание, причина, что сказать, что сделать.

## Что считается успехом

- Глава читается как набор карточек; общий объём 900–1400 слов, ни одна карточка не длиннее 90 слов.
- В каждой ситуации есть: сцена («узнаёшь себя?»), причина («почему так» со ссылкой на черты), 1–3 готовые фразы, одно действие.
- Не более одного «может/возможно/можно сравнить» на карточку; нет фраз-пустышек («в моей конкретной ситуации»).
- Нет стоп-слов (диагнозы, лечение и т. п.): прежняя проверка `findStopWords` сохраняется.
- Старые главы (формат 1) открываются как раньше. Откат — выключением флага без потери данных.

## Что НЕ входит в пилот

Другие три главы, полный разбор, картинка-карточка «моё правило» и PDF-памятка главы, исправление контраста в `PersonalEdition.module.css` (отдельная правка), перестройка вкладок «Личного атласа».

## Дизайн

### 1. Формат данных (`packages/ai/src/sections.ts`)

Глава принимает два формата, различаемых полем `version`:

- формат 1 — как сейчас `{text, tips}` (без поля `version`);
- формат 2:

```ts
{
  version: 2,
  headline: string,            // 40–140 знаков, главный вывод одной строкой
  summary: string,             // 150–500 знаков
  situations: Array<{          // 5–6 штук, по одной на «тему» из списка тем главы
    seed: string,              // id темы из chapter-seeds
    title: string,             // 20–90 знаков
    scene: string,             // 80–320 знаков, «узнаёшь себя?»
    why: string,               // 80–320 знаков, связь черт: почему так
    traits: Trait[],           // 1–2 черты, на которых держится вывод
    say: string[],             // 1–3 фразы, по 10–160 знаков
    do: string,                // 40–260 знаков, одно действие
  }>,
  others_see: string,          // 120–400 знаков, как это видят близкие
  traps: Array<{ trap: string; instead: string }>,  // ровно 3 штуки
}
```

График по пяти чертам, вопросы для самопроверки и ссылка на компас считаются в коде и в ответе модели не участвуют. Запись в таблице `reports.sections` (jsonb) не меняется, миграция БД не нужна.

`parseSections("chapter_*", value)` возвращает объединённый тип. Все места, читающие `sections.text`/`tips` (`report-view.ts`, обычная страница разбора, `PersonalEdition`), разбирают оба формата.

### 2. Темы главы (`packages/content/src/chapter-seeds.ts`, новый файл)

Редакционный список тем для каждой сферы. Для «Денег» — шесть: «Помощь другим и отказ», «Неожиданные траты», «Покупки для настроения», «Новые возможности и предложения», «Периоды: учёт и спонтанность», «Общие деньги и разговор о них». У темы: `id`, `title` (показывается и до покупки), `traits` (какие блоки передавать) и короткая `focus` (что именно разобрать). Темы гарантируют, что карточки не повторяются и что структура одинакова у всех покупателей.

### 3. Генерация — три коротких запроса (`packages/ai/src/generate-chapter.ts`, новый файл)

Запросы идут параллельно:

1. **overview** — `headline`, `summary`, `others_see`, `traps` (получает все пять черт и все блоки);
2. **situations A** — темы 1–3;
3. **situations B** — темы 4–6.

Каждый запрос — до 3 попыток, таймаут 60 с (как сейчас); ответ проходит схему, стоп-слова и новые проверки (п. 4). Если хоть одна часть не удалась после трёх попыток, вся глава собирается прежним `fallbackSections` в формате 1 и сохраняется с `source = "fallback"`. Так «дыры» в главе не появляются, а поведение при сбое то же, что сейчас.

### 4. Инструкция и проверки

Новая инструкция (на основе `COMMON_RULES`):

- пиши на «ты», без родовых окончаний, как раньше;
- опирайся на баллы и блоки, но ситуации можно давать как **примеры** («например, друг просит денег»), а не как факты о читателе: запрещены утверждения о прошлом читателя («ты уже…», «у тебя было…»);
- «что сказать» — готовые фразы в кавычках, которыми можно сразу воспользоваться;
- не более одной оговорки («может», «возможно», «можно сравнить») на карточку; общая оговорка вынесена в подпись под главой;
- не пересказывай блоки слово в слово: объясняй, почему так и что делать.

Валидатор (`validate.ts`) дополняется: длины полей, число элементов, уникальность `seed`/`title`, ограничение числа оговорок, запрет списка фраз-пустышек. Стоп-слова — обязательно для всех строк.

### 5. Включение

Генерация формата 2 включается переменной воркера `CHAPTER_CARDS_V2=1` (по умолчанию выключена, остальные главы не затрагиваются: флаг действует только на `chapter_money`). Страница читает оба формата независимо от флага. Откат: убрать переменную; уже созданные главы формата 2 продолжают открываться.

### 6. Страница главы (`PersonalEdition` и обычная страница разбора)

Новый компонент `ChapterCards`:

- шапка: камень сферы, `headline`, `summary`;
- график: три оси для «Денег» (считаются по баллам, `chapterAxes()` в `apps/web/src/lib/`), например «осторожность с новым — лёгкость отказать — спокойствие при неожиданных тратах»;
- карточки ситуаций (сцена → «почему так» → «что сказать» → «что сделать»);
- «Как это видят близкие» и «Три ловушки»;
- завершение: ссылка на существующий «финансовый компас» (`/report/[id]/practice/money`) вместо отдельного плана недели.

Вёрстка читается на 390 px; заголовки внутри главы получают `scroll-margin-top`, чтобы липкая навигация их не перекрывала. Все элементы тёмной темы — без новых бежевых «бумажных» блоков.

Для ещё не купленной главы карточка «Что внутри» показывает **реальные названия шести тем** из `chapter-seeds` (персонализированного текста до покупки нет, и он не выдумывается).

### 7. Тесты

- схема: оба формата, границы длин, дубли;
- валидатор: оговорки, фразы-пустышки, стоп-слова;
- генерация главы: три части, повтор, откат на формат 1 при сбое одной части;
- прежние тесты глав и отчётов остаются зелёными;
- рендер: оба формата, неготовая глава, непокупка;
- e2e: покупка главы «Деньги» на фейковом провайдере → карточки видны на 1440 и 390 px.

Покрытие нового кода — не ниже 80 %.

## Риски и допущения

- **Качество текста** оценивается только с боевым ключом YandexGPT. Ключ владелица кладёт в локальный `.env` сама. Без него проверяются формат, разбор и откат; в этом случае качество текста можно оценить только после выкладки.
- **Стоимость:** 3 запроса вместо 1 на каждую покупку главы; при цене 99 ₽ незначительна.
- Прежние 4 главы в базе — тестовые (формат 1), их можно оставить или пересоздать вручную.
- Общий предел «900–1400 слов» — целевой, не жёсткий: валидатор проверяет границы полей.
